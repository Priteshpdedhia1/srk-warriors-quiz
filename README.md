# SRK Warriors Quiz

A real-time, Kahoot-style live quiz built around Shah Rukh Khan trivia. The host runs the game on a big screen / projector while players join from their phones using a game PIN (or QR code). Questions appear on the host screen; players tap their answers on their devices; the server keeps an authoritative timer, scores answers, and drives a live leaderboard, per-question reveals, and a podium finale — all over WebSockets so the room stays perfectly in sync.

## Features (v1)

- **Landing page** with quick paths to join a game or host one.
- **Host login** (single shared host password) issuing a JWT for the host console.
- **Create game** with an auto-generated join **PIN + QR code** for instant device joining.
- **Lobby** showing players streaming in live before the game starts.
- **40 questions**, 30 seconds each, 1 point per correct answer.
- **Server-authoritative timer** — the server owns the clock, so all clients stay synchronized and can't game the countdown.
- **Scoring with winner tiebreak chain** — ties are broken by a deterministic sequence of tiebreakers to always produce a clear winner.
- **Per-question reveal** with a **bar chart** of how the room answered.
- **Live leaderboard** updated between questions.
- **Host analytics + full controls** — start, skip, reveal, advance, and end the game; live stats for the host.
- **Audio FX** for lobby, countdown, reveal, and celebration moments.
- **Auto-reconnect** — players who drop briefly rejoin their session and score.
- **Anti-cheat**: one answer per question per player, the `correctIndex` is never leaked to clients before reveal, duplicate submissions are de-duped, and a back-navigation guard prevents re-answering.

## Local Development

### Prerequisites
- **Node 18+**
- A free **Neon Postgres** database — create one at [neon.tech](https://neon.tech).

### Windows / OneDrive note (important)
If the project lives under a OneDrive-synced folder, **pause OneDrive sync during `npm install`**. OneDrive can hold file locks while Prisma and esbuild write into `node_modules`, causing `EPERM` / `EBUSY` errors. If install fails on `@prisma/debug` or `esbuild`, pause OneDrive and run `npm install` again.

### Steps

1. **Configure the server environment**
   Copy `server/.env.example` to `server/.env` and set:
   - `DATABASE_URL` — your Neon Postgres connection string
   - `HOST_PASSWORD` — host login password (default: `srkwarriors`)
   - `JWT_SECRET` — any long random string
   - `CORS_ORIGIN=http://localhost:5173`

2. **Configure the client environment**
   Copy `client/.env.example` to `client/.env` and set:
   - `VITE_SERVER_URL=http://localhost:4000`

3. **Install dependencies** (from the repo root):
   ```bash
   npm install
   ```

4. **Push the database schema** to Neon:
   ```bash
   npm --workspace server run prisma:push
   ```

5. **(Optional) Seed questions manually.**
   Questions auto-seed on the first server boot, but to reseed manually (wipes and re-inserts the bank):
   ```bash
   npm --workspace server run seed
   ```

6. **Run both apps** (server on :4000, client on :5173):
   ```bash
   npm run dev
   ```

### Host password
The host logs in with `srkwarriors` by default. Override it via the `HOST_PASSWORD` env var.

## Deployment (free tier)

The whole stack runs on free tiers: **Neon** (Postgres) + **Render** (server) + **Vercel** (client).

### 1. Database — Neon
Create a free Neon project and copy the **pooled** connection string. Use it as `DATABASE_URL` on the backend.

### 2. Backend — Render
Create a **New Web Service** from this repo. Render picks up `render.yaml` automatically (`rootDir: server`, `plan: free`). Set these env vars:
- `DATABASE_URL` — your Neon pooled connection string
- `HOST_PASSWORD` — your host password
- `CORS_ORIGIN` — your Vercel front-end URL

`JWT_SECRET` is auto-generated by Render. On deploy, tables auto-create via `prisma db push`, and the question bank auto-seeds on first boot (idempotent — it only seeds when the table is empty and never wipes existing data).

### 3. Frontend — Vercel
Import the repo into Vercel and set:
- **Root Directory**: `client`
- **Framework**: Vite
- **Build Command**: `npm run build`
- **Output Directory**: `dist`
- **Env**: `VITE_SERVER_URL` = your Render backend URL

`client/vercel.json` rewrites all routes to `index.html` so SPA deep links (e.g. shared join URLs) work.

### Free-tier caveat (cold starts)
Render free web services **sleep after ~15 minutes idle** and take roughly 50 seconds to cold-start. Before your event, warm it up: point a free uptime pinger (e.g. [cron-job.org](https://cron-job.org) or [UptimeRobot](https://uptimerobot.com)) at `https://<your-render-url>/health` every ~10 minutes. Once players connect, the live socket traffic keeps the service awake.
